기준일: **2026-10-13** · 조사 기준 커밋: **`2530c76`**

README는 현재 코드, 최종 결과 보고서, 발표 자료를 대조해 작성했다. 기획서는 초기 의도와 계획 확인에 사용했다.

## 빌드 검증

- MSBuild **18.10.1.42706**
- 설치된 MSVC 도구 버전 **14.51.36231**, 프로젝트 도구 집합 **v145**
- `Release | x64`, C++20, Windows SDK 10.0 계열, 프로젝트 원본 설정 사용
- 최종 결과: **컴파일 및 링크 성공, 경고 0 / 오류 0**, `No_Save_Love.exe` 생성
- 검증 산출물은 저장소 밖의 임시 폴더로 지정하여 기존 배포본을 보존했다.
- 성공한 빌드는 **`PreferredToolArchitecture=x64`**를 명시했다.

저장소 루트의 Visual Studio 개발자 PowerShell에서 사용하는 기본 명령:

```powershell
msbuild .\No_Save_Love\No_Save_Love\No_Save_Love.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64 /p:PreferredToolArchitecture=x64
```

이번 검증에서는 여기에 임시 `OutDir`·`IntDir`를 추가했다. 프로젝트 파일을 수정하거나 도구 집합을 다른 버전으로 바꾸지 않았다.

처음에는 샌드박스 기본 임시 경로의 빌드 상태 파일 쓰기에서 `MSB3491`이 발생했다.
허용된 사용자 임시 폴더를 사용한 다음 빌드에서는 링크 단계에서 `LNK1101: MSPDB140.DLL 버전이 잘못되었습니다`가 발생했다.
같은 소스·구성에서 x64 호스트 도구를 지정한 빌드는 성공했다. 이 결과만으로 DLL 설치 문제의 원인을 확정하지는 않는다.

## 실행 검증의 범위

이 작업 환경의 UI 도구는 Windows 네이티브 게임 창 조작·촬영을 지원하지 않는다.
따라서 **새 실행 파일과 기존 배포 EXE를 직접 플레이하지 않았으며**, 기존 자료의 플레이 화면을 사용했다.
빌드 성공은 플레이 완주·오디오·분기 전체의 정상 동작을 증명하지 않는다.

후속으로 확인할 실행 항목:

- 일반 진행으로 미니게임 1–4, 결과·인물 선택·엔딩 연결 완주
- 세 인물의 해피/배드와 공통 히든 엔딩, 선택 횟수 동률 처리
- 리듬게임 창 변화 이후 입력 좌표·커서·원래 창 복원
- 이미지 로딩, BGM과 효과음, 종료 확인창
- 1920×1080 외 해상도와 Windows DPI 배율
- 기존 배포본과 현재 소스 빌드의 동작 일치 여부

## 현재 코드와 설명에서 구분한 점

- **등교길 점수:** 튜토리얼에는 거리로 점수가 오른다는 문장이 있지만, `schoolrun::GetScore()`는 젤리 수집 비율을 사용한다. README는 실제 점수 코드를 따른다.
- **유혹피하기 점수:** 남은 체력 × 20점이다. 생존 시간이 직접 점수로 환산되는 것으로 소개하지 않았다.
- **업데이트 간격:** 메인 타이머는 60ms다. 일부 미니게임은 업데이트당 고정 시간값을 사용하므로, 이를 60FPS나 측정된 실시간 플레이 길이로 표현하지 않았다.
- **분기 선택:** 각 미니게임 뒤의 인물 선택을 누적한다. 모든 대사에 선택지가 있는 구조나 마지막 독립 선택 메뉴로 설명하지 않았다.
- **대사 데이터:** C++ 구조체와 벡터로 분리되어 있지만 외부 스크립트 파일을 실시간 로드하는 시스템은 아니다.
- **개발용 입력:** `F1`–`F4`, `Q`는 Release에서도 활성화되어 있다.
- **타이틀 이미지:** 새 파일명이 없을 때 기존 PNG를 읽는 fallback이 구현되어 있다. 없는 신규 이미지를 준비 완료로 소개하지 않았다.

## 개인 포트폴리오로 확장할 때

확인된 팀 역할은 [크레딧](CREDITS.md#팀-역할)에 정리했다. 아래 항목은 본인의 설명 또는 추가 근거가 필요하다.

1. **공통 코드의 담당 범위:** 직접 설계·구현·수정한 매니저와 Scene, 공동 작업 경계
2. **한 가지 구체적인 문제 해결 사례:** 증상, 원인, 선택한 해결책, 다른 방법과의 비교, 실제 확인 방식

4. **자산 사용 조건:** 외부 음원·효과음·폰트의 파일별 출처와 허가 근거

확인 전에는 기여율, 성능 수치, 단독 제작, 전체 기능 테스트 완료를 추가하지 않는다.
