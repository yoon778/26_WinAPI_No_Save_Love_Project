# 미니게임 성장 밸런스

## 목표와 판정 기준

스토리 진행에 필요한 실력 기준을 B등급 중상위로 잡는다. 현재는 네 게임을 한 번씩 플레이하고 스탯 0에서 시작한다. 네 게임 모두 70점이면 각 스탯 62, 히로인별 핵심 스탯 합 124로 해피 엔딩에 도달한다. 잘한 게임의 보상으로 일부 실수를 만회할 수 있지만, 한 게임의 만점만으로 해피 엔딩을 보장하지 않는다.

기존 엔딩 조건은 유지한다. 총합 80 이하는 히든, 그 외에는 세아의 재력+대화, 하린의 대화+매력, 이린의 매력+외모가 120 이상일 때 해피다. 최종 히로인을 정하는 선택 횟수 규칙도 유지한다. 단순 평균 점수만으로 모든 루트의 엔딩이 결정되지는 않는다.

## 현재 4개 게임의 증가량

| 환산 점수 | 등급 | 주 스탯 | 보조 스탯 |
| --- | --- | ---: | ---: |
| 0 | F | +0 | +0 |
| 20 | D | +10 | +6 |
| 40 | C | +20 | +12 |
| 50 | C | +28 | +17 |
| 60 | B | +35 | +21 |
| 70 | B | +39 | +23 |
| 80 | A | +43 | +26 |
| 90 | S | +46 | +28 |
| 100 | S | +50 | +30 |

표 사이 점수에도 보상이 계산된다. 등급은 성적 표시용이며, 같은 B라도 60점과 79점의 보상은 다르다. 0점 보상은 0이고, F등급도 실제 점수에 따라 소량 성장한다. 소수는 최종 증가량에서 반올림하므로 모든 1점 상승이 반드시 스탯 상승으로 이어지지는 않는다.

| 게임 | 주 스탯 | 보조 스탯 | 현재 점수 환산 방식 |
| --- | --- | --- | --- |
| PC방 알바 | 재력 | 대화 스킬 | 50초, 성공 +100 / 오배달 -50, 원점수 1000이 환산 100점 |
| 노래 연습 | 매력 | 외모 | 108초, 콤보 보너스를 포함한 최종 점수 / 27500 × 100 |
| 등교길 | 외모 | 매력 | 전체 젤리 대비 수집률, 정수 수집률 85 초과면 100점 |
| 유혹 피하기 | 대화 스킬 | 재력 | 50초, 남은 하트 5개 기준으로 0·20·40·60·80·100점 |

이번 수정은 환산 점수를 받는 이후의 스탯 보상만 조정한다. 원점수, 조작 난이도, 제한 시간, 등급 경계는 변경하지 않는다. 특히 회피 게임의 70점은 실제로 나오지 않으므로, 모든 게임 70점 예시는 공통 보상 곡선의 비교 기준이다.

## 성장 곡선과 보상 총량

`StatBalance.h`에서 한 회차의 스탯별 최대 획득량을 80으로 고정한다. 네 스탯 합계는 최대 320이며, 기존 UI의 개별 스탯 상한 100과는 구별한다. 만점 보상은 기존 4게임 구성과 같다.

만점 대비 지급률은 점수 0·40·60·100에서 각각 0%·40%·70%·100%다. 기준점 사이에서는 선형으로 증가한다. 40~60점 구간의 성장률을 높여 기본 조작을 익힌 성과를 보상하고, 60점 이후에는 완만하게 증가시킨다. 기존의 79→80, 89→90 등급 경계에서 갑자기 보상이 뛰는 현상을 없앤다.

게임마다 주 스탯 비중 5, 보조 스탯 비중 3을 등록한다. 스탯별로 모든 게임의 비중을 더한 뒤 해당 스탯의 80을 나눈다. 정수 배분은 누적 비중으로 계산해 모든 게임 만점 시 정확히 80이 되게 한다. 같은 성적을 받아도 5~6개 구성에서는 반올림 때문에 중간 점수의 합계가 조금 달라질 수 있다.

## 1~2개 추가 시 적용

게임 개수만으로 전체 보상에 `4 / 게임 수`를 곱하지 않는다. 새 게임이 대화만 올려 준다면, 재력·외모 보상까지 줄여서는 루트 균형이 깨진다. **새 게임이 담당하는 스탯의 보상만 재배분**한다.

아직 구현하지 않은 게임은 `GameWeights`에 미리 넣지 않는다. 현재의 실제 4개 게임만 등록되어 있다. 확장 검증에서는 아래 두 구성을 가정했다. 이는 새 게임의 확정 기획이 아니다.

- 5개 구성: 대화 비중 5 / 매력 비중 3인 게임 추가.
- 6개 구성: 위 구성에 외모 비중 5 / 재력 비중 3인 게임 추가.

| 가정 구성 | 모든 게임 60점의 스탯 | 모든 게임 70점의 스탯 | 모든 게임 만점의 스탯 |
| --- | --- | --- | --- |
| 4개 | 56 / 56 / 56 / 56 | 62 / 62 / 62 / 62 | 80 / 80 / 80 / 80 |
| 5개 | 56 / 57 / 55 / 56 | 62 / 62 / 62 / 62 | 80 / 80 / 80 / 80 |
| 6개 | 55 / 57 / 55 / 57 | 62 / 62 / 62 / 62 | 80 / 80 / 80 / 80 |

순서는 재력 / 대화 / 매력 / 외모다. 위 구성은 모두 60점이면 배드, 70점이면 해피다. 재력에만 비중 8을 주는 다섯 번째 게임도 별도로 검증했다.

추가 구현 때는 다음을 함께 연결해야 한다.

1. 새 게임의 결과 점수를 0~100으로 환산하고 성장할 스탯 비중을 `GameWeights`에 등록한다.
2. `GameManager`의 모드·튜토리얼·종료 처리·진행 횟수와 결과 화면의 게임 이름을 추가한다. 보상 표 등록만으로 새 게임이 실행되는 것은 아니다.
3. 추가 게임의 삽입 위치에 맞게 스토리 회차와 히로인 선택 횟수를 검토한다. 현재 스토리와 선택은 4회다.
4. 확정된 비중으로 `tests/run_stat_checks.ps1`의 확장 사례를 바꾸고, 실제 초보자 점수 분포를 확인한다.

## 검증 결과와 남은 플레이 테스트

- 현재 4개 구성에서 20점씩이면 총합 64로 히든, 40점씩이면 핵심 합 64로 배드, 60점씩이면 핵심 합 112로 배드, 70점씩이면 핵심 합 124로 해피다.
- 실제 가능한 점수 조합 `60 / 80 / 80 / 80`은 스탯 `61 / 64 / 69 / 69`로 세 루트 모두 해피다.
- `80 / 80 / 80 / 40`은 세아 배드, 이린 해피다. 잘한 게임과 선택한 인물의 연결은 남아 있다.
- C++ 테스트로 전체 0~100점의 보상 단조 증가, 잘못된 게임 번호, 점수 범위 제한, 결과 화면의 실제 보상 연결, 엔딩 80/81·119/120 경계, 4·5·6개 구성의 최대 총량을 확인했다.
- x64 Release 빌드가 통과했다. 수치와 코드 검증에 따른 1차 튜닝이며, 실제 플레이어의 클리어율을 측정한 결과는 아니다. 회피 게임의 하트 점수 간격과 리듬게임의 긴 플레이 시간은 후속 플레이 테스트에서 별도로 확인한다.

실행: 프로젝트 폴더에서 `powershell -ExecutionPolicy Bypass -File tests/run_stat_checks.ps1`.
