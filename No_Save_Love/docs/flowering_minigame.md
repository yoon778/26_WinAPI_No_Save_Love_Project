# 개화 — 금요일의 작은 무대

## 진행과 조작

네 번째 만남 → 가장 많이 만난 히로인과 공연 준비 → 튜토리얼 → 개화 공연 → 결과와 성장 → 히로인의 감상 → 기존 최종 이야기와 엔딩 순서다. 인물 선택은 기존 네 번을 유지한다. 세아·하린·이린별 공연 전후 대사 22개씩, 합계 66개를 추가했다.

기존 리듬게임의 클릭 / 누른 채 슬라이더 따라가기를 사용한다. 공연 중 `Esc`로 조작 안내를 열면 음원과 판정도 함께 멈추고, 취소하면 이어진다. 개발용 `F5`는 바로 공연 시작 / 재시작, `Q`는 현재 점수로 종료다. 디버그 바로가기는 이전 선택·보상을 새 회차로 초기화하지 않으므로 정규 엔딩 테스트와 구별한다.

## 다섯 가지 기믹

| 기믹 | 첫 등장 약 | 플레이 |
| --- | ---: | --- |
| 바람 슬라이더 | 33초 | 휘는 꽃길의 공을 누른 채 따라간다. 렌더와 판정이 같은 곡선을 사용한다. |
| 기억 꽃 | 44초 | 보라색 노트는 판정 직전 0.25초 동안 숨는다. 위치·박자는 그대로다. |
| 히로인 릴레이 | 59초 | 히로인의 응원과 꽃 네 위치를 보고, 이어지는 노트를 같은 순서로 친다. 시범 꽃에는 클릭 판정이 없다. |
| 앵콜 노트 | 67초 | 같은 자리를 한 박자 간격으로 두 번 누른다. 반복 화살표와 다시 줄어드는 접근 원, 두 점으로 입력 순서를 표시한다. 두 번째 입력 뒤 다음 노트까지 세 박자(약 1.385초)를 확보한다. |
| 이어치기 | 83초 | 청록색 1·2번 원을 화살표 방향으로 두 박자 간격으로 누른다. 드래그하지 않는다. 첫 입력 전에 두 번째 목적지를 미리 보여준다. |

약 96초부터 267초까지 곡선·기억 꽃·앵콜·이어치기를 섞는다. 릴레이도 약 137초와 200초에 다시 등장한다. 마지막 구간은 피날레 조명으로 바뀐다. 등장 전 아래쪽 안내를 띄우고, 슬라이더 유지 중 다른 위치를 클릭하는 배치는 만들지 않는다. 히로인은 오른쪽에서 박자에 맞춰 움직이고 콤보에 따라 웃는다. 성공으로 핀 무대 아래 꽃은 실수해도 사라지지 않는다. 꽃잎·조명·꽃길은 GDI+로 그린다.

## 음원과 채보

- 제공받은 `[MV] LUCY  - 개화(Flowering) ENG sub.mp3`를 `resource/minigame5/sound/flowering.mp3`로 원본 그대로 복사했다.
- **원곡 전체 약 272.34초(4분 32초)**를 재생한다. 실제 재생 길이는 Windows MCI에서 읽는다. 120초 중간 절단과 인위적인 볼륨 페이드를 제거했고 마지막 노트 이후 원곡 여운까지 듣는다. MP3를 자르거나 재인코딩하지 않는다.
- Windows Media Foundation으로 PCM을 분석한 **130 BPM / 기준 오프셋 130ms**의 1차 채보다. 음원 재생 위치를 직접 조회하여 프레임 지연이나 일시정지로 음악과 판정 시간이 따로 흐르지 않게 한다.
- 첫 노트 약 3.82초, 접근 시간 1.2초, 총 225개 노트 중 슬라이더 33개. 클릭 판정 300/100/50점, 슬라이더 완주 추가 300점, 원점수 만점 77,400점이다. 공연의 PERFECT 허용 범위는 ±110ms, GOOD은 ±190ms다. 기존 노래 연습의 판정과 콤보 가산 방식은 유지한다.
- 원본/복사본 SHA-256: `61C0BD829A9BEFB130F659F04CD17FE9BD60D05A376C09F3E88C48D0379D911A`.

## 등급 환산

공연은 성공률 90% + 박자 정확도 10%로 환산한다. 클릭 성공과 슬라이더 완주를 각각 한 판정 단위로 계산하며, 총 258단위다. 잘못 누른 위치나 놓친 노트, 슬라이더 중단은 성공 단위를 얻지 못한다. 모든 단위를 성공하면 BAD 위주여도 S등급이고, 전부 PERFECT면 100점이다. 노래 연습(게임 2)의 기존 환산은 바꾸지 않는다.

실제 입력 경로에 140ms 지연을 넣은 전곡 검사는 94점 S, 220ms 지연 검사는 93점 S다. 모든 노트를 놓친 경우 0점이다. 결과 화면에 성공 단위와 환산 비중을 함께 표시한다.

## 구현 위치

- `minigame2/FloweringChart.h`: 구간·박자·좌표·기믹 플래그와 만점 계산.
- `minigame2/RhythmMiniGame.cpp/.h`: 기존 엔진에 개화 모드, 음원 선택, 음악 시각 기반 판정, 성공 단위 누적, 원곡 자연 종료·해제 연결.
- `minigame2/RhythmMiniGameFlowering.cpp`: 곡선 좌표, 숨김·앵콜 표시, 무대·히로인·꽃 효과, 오디오 일시정지.
- `GameManager.cpp`, `StoryData.cpp`, `Scenes/MiniGame2TutorialScene.cpp`: 다섯 번째 게임 진행, 히로인별 전후 이야기, 전용 안내.
- `StatBalance.h`, `Scenes/ResultScene.cpp`: 대화/매력 보상, 게임 이름. 자세한 수치는 [성장 밸런스](minigame_balance.md).

게임 실행은 WinAPI C++만 사용한다. 파형 분석용 개발 도구는 런타임 의존성이 아니다.

## 검증과 남은 조정

`tests/run_flowering_checks.ps1`은 실제 MP3 열기·재생·시간·일시정지·재개·원곡 마지막 프레임 종료를 검사한 뒤, 같은 게임 판정 코드에 음악 시각을 공급하여 전 채보 만점, 전곡 GOOD/BAD 성공의 S등급, 전체 실패, 재시작, 기억 꽃 숨김 경계, 앵콜 겹침, 후반의 모든 기믹 등장, 기존 게임2 점수·창 복구를 확인한다. 히로인 세 명 모두 튜토리얼→공연→보상→공연 후 이야기→기존 엔딩 흐름도 검사한다. Windows 오디오에 접근 가능한 환경에서 실행한다.

`tests/run_story_checks.ps1`: 32개 대사 배열 2007개 항목(공유 엔딩 중복 포함), 기존 CG 7개·스토리 애니메이션 22종·표현 변형 22종과 대사 표시·입력·초기화를 검사한다. `tests/run_stat_checks.ps1`: 4/5/6게임 보상·엔딩 경계를 검사한다.

앵콜 시각 안내는 [osu!의 반복 슬라이더](https://osu.ppy.sh/wiki/en/Gameplay/Hit_object/Slider/Repeat_slider)의 반복 화살표를 참고했다. 같은 위치에서 두 번 클릭하는 기존 규칙은 유지하며, 화살표·접근 원·발광을 GDI+로 직접 그린다. 외부 스킨 이미지를 복사하지 않는다.

사람이 전곡을 직접 플레이하며 체감 난이도와 음표별 청감을 조정한 단계는 아니다. 현재 채보는 파형 분석과 자동 판정 검사를 통과한 초안이다.
