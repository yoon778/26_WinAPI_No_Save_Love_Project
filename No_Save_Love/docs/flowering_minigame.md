# 개화 — 금요일의 작은 무대

## 진행과 조작

네 번째 사건 뒤 다섯 번째 동행을 선택하고 전술 디펜스와 전후 이야기를 진행한다. 노트의 다섯 장을 채운 뒤 가장 많이 선택한 히로인과 공연 준비, 튜토리얼, 개화 공연, 결과와 성장, 감상, 최종 이야기와 엔딩으로 이어진다. 인물 선택은 총 다섯 번이며 공연 이후에는 추가 선택이 없다. 공연 전후 대사는 세아·하린·이린별 23개씩, 합계 69개다.

기존 리듬게임의 클릭 / 누른 채 슬라이더 따라가기를 사용한다. 공연 중 `Esc`로 조작 안내를 열면 음원과 판정도 함께 멈추고, 취소하면 이어진다. 개발용 `F6`는 바로 공연 시작 / 재시작, `Q`는 현재 점수로 종료다. 디버그 바로가기는 이전 선택·보상을 새 회차로 초기화하지 않으므로 정규 엔딩 테스트와 구별한다.

## 여섯 가지 기믹

| 기믹 | 첫 등장 약 | 플레이 |
| --- | ---: | --- |
| 바람 슬라이더 | 33초 | 휘는 꽃길의 공을 누른 채 따라간다. 렌더와 판정이 같은 곡선을 사용한다. |
| 기억 꽃 | 44초 | 보라색 꽃과 입자로 위치를 예고한 뒤 꽃을 숨긴다. 보이지 않는 원래 위치를 박자에 맞춰 누른다. 숨김은 스토리/보통/도전에서 판정 450/550/650ms 전부터 판정 120ms 뒤까지다. |
| 히로인 릴레이 | 59초 | 네 위치가 빛나는 순서를 먼저 본다. 예고가 끝나면 네 노드가 동시에 활성화되며, 예고된 순서대로 누른다. 시범에는 클릭 판정이 없고 기억 꽃의 숨김 규칙도 적용하지 않는다. |
| 앵콜 노트 | 74초 | 같은 자리를 한 박자 간격으로 두 번 누른다. 반복 화살표와 다시 줄어드는 접근 원, 두 점으로 입력 순서를 표시한다. 두 번째 입력 뒤 다음 노트까지 세 박자(약 1.385초)를 확보한다. |
| 왕복 슬라이더 | 83초 | 시작점을 누른 채 공을 따라간다. 끝의 반전 화살표에서 같은 꽃길을 되돌아와야 완주한다. 왕복에 네 박자를 쓰고 다음 노트까지 두 박자를 확보한다. |
| 스피너 | 96초 | 버튼을 누른 채 중심 주위를 어느 방향이든 회전한다. 스토리/보통/도전은 각각 2/3/4바퀴를 채우면 성공한다. 여덟 박자 동안 진행하며 다른 노트를 동시에 요구하지 않는다. |

약 96초부터 247초까지 기믹을 섞는다. 릴레이는 약 137초와 200초에 다시 등장하며 위치의 순서도 달라진다. 네 입력을 완료하는 시간은 여덟 박자다. 순서를 잘못 누르면 콤보가 끊기고 안내가 나오지만 노드는 남으므로, 기한 안에 올바른 순서로 다시 이어갈 수 있다. 스피너는 약 163초와 236초에도 등장한다. 버튼을 놓거나 일시정지하면 회전을 집계하지 않는다. 중심 바로 근처나 너무 먼 위치, 갑작스러운 큰 각도 이동도 집계하지 않는다.

기존 이어치기는 제거했다. 마지막 구간은 피날레 조명으로 바뀐다. 등장 전 아래쪽 안내를 띄우고, 슬라이더 유지 중 다른 위치를 클릭하는 배치는 만들지 않는다. 히로인은 오른쪽에서 박자에 맞춰 움직이고 콤보에 따라 웃는다. 성공으로 핀 무대 아래 꽃은 실수해도 사라지지 않는다. 꽃잎·조명·꽃길은 GDI+로 그린다.

## 음원과 채보

- 제공받은 `[MV] LUCY  - 개화(Flowering) ENG sub.mp3`의 끝에 붙은 약 20.35초 디지털 무음을 제거하여 `resource/minigame5/sound/flowering.mp3`로 사용한다.
- **공연 약 252.006초(4분 12초)**를 재생한다. 실제 재생 길이는 Windows MCI에서 읽는다. 연주와 잔향은 보존하며 마지막 왕복 슬라이더가 끝난 뒤 약 4.5초의 여운을 남긴다. 중간 절단이나 인위적인 볼륨 페이드를 적용하지 않는다.
- Windows Media Foundation으로 PCM을 분석한 **130 BPM / 기준 오프셋 130ms**의 1차 채보다. 음원 재생 위치를 직접 조회하여 프레임 지연이나 일시정지로 음악과 판정 시간이 따로 흐르지 않게 한다.
- 첫 노트 약 3.82초, 보통 난이도 접근 시간 1.2초다. 현재 채보는 175개 오브젝트·202개 판정 단위·원점수 만점 60,600점이다. 클릭 판정은 300/100/50점이며 슬라이더 완주는 추가 300점, 스피너 완수는 300점이다. 릴레이는 기한 안에 순서대로 누른 각 노드에 300점을 준다. 노트 수와 원점수 만점은 채보에서 계산한다. 보통 난이도 공연의 PERFECT 허용 범위는 ±110ms, GOOD은 ±190ms다. 기존 노래 연습의 판정과 콤보 가산 방식은 유지한다.
- 무음 제거 음원 SHA-256: `4A91B400AFBD23D700196E21C175196014EBB20B24A08F30460DF55FC62DEA53`.

## 등급 환산

공연은 성공률 90% + 박자 정확도 10%로 환산한다. 클릭 성공, 슬라이더 완주, 스피너 완수를 각각 한 판정 단위로 계산한다. 잘못 누른 위치나 놓친 노트, 슬라이더 중단은 성공 단위를 얻지 못한다. 모든 단위를 성공하면 BAD 위주여도 S등급이고, 전부 PERFECT면 100점이다. 노래 연습(게임 2)의 기존 환산은 바꾸지 않는다.

실제 입력 경로에 140ms 지연을 넣은 전곡 검사는 95점 S, 220ms 지연 검사는 93점 S를 확인했다. 모든 노트를 놓친 경우는 0점이며 실패 202단위다. 결과 화면에 성공 단위와 환산 비중을 함께 표시한다.

## 구현 위치

- `minigame2/FloweringChart.h`: 구간·박자·좌표·기믹 플래그와 만점 계산.
- `minigame2/RhythmMiniGame.cpp/.h`: 기존 엔진에 개화 모드, 음원 선택, 음악 시각 기반 판정, 성공 단위 누적, 원곡 자연 종료·해제 연결.
- `minigame2/RhythmMiniGameFlowering.cpp`: 왕복·곡선 좌표, 숨김·릴레이·앵콜·스피너 표시와 판정, 무대·히로인·꽃 효과, 오디오 일시정지.
- `GameManager.cpp`, `StoryData.cpp`, `Scenes/MiniGame2TutorialScene.cpp`: 여섯 번째 게임 진행, 히로인별 전후 이야기, 전용 안내.
- `StatBalance.h`, `Scenes/ResultScene.cpp`: 대화/매력 보상, 게임 이름. 자세한 수치는 [성장 밸런스](minigame_balance.md).

공연은 여섯 번째 게임이지만 기존 음원 경로 `resource/minigame5/`는 호환성을 위해 유지한다. 게임 실행은 WinAPI C++만 사용한다. 파형 분석용 개발 도구는 런타임 의존성이 아니다.

노래 연습(게임 2)은 `RhythmPracticeEffects.h`의 GDI 연출을 사용한다. 음악 시각에 맞춘 가장자리 조명, 성공·실패 반응, 콤보 강조, 슬라이더 진행 표시와 창 기믹 단계별 조명이 노트 영역을 가리지 않도록 배경에 그려진다. 별도 타이머나 입자 배열을 만들지 않으며, 일시정지 중에는 게임 시각과 함께 연출도 멈춘다. `tests/rhythm_practice_effects_check.h`에서 시간 변화·효과 만료·단계 구별·노트 영역 보호·GDI 상태 복구와 자원 누수를 검사하고 렌더 비용을 기록한다.

## 검증과 남은 조정

`tests/run_flowering_checks.ps1`은 실제 MP3 열기·재생·시간·일시정지·재개·약 252초 마지막 프레임 종료를 검사한 뒤, 같은 게임 판정 코드에 음악 시각을 공급하여 전 채보 만점, 전곡 GOOD/BAD 성공의 S등급, 전체 실패, 재시작, 후반의 모든 기믹 등장, 기존 게임2 점수·창 복구를 확인한다. 히로인 세 명 모두 튜토리얼→공연→보상→공연 후 이야기→기존 엔딩 흐름도 검사한다. Windows 오디오에 접근 가능한 환경에서 실행한다.

기믹별 검사는 난이도별 기억 꽃 숨김 경계, 앵콜 겹침, 릴레이 예고 중 입력 무시·네 노드 동시 활성화·잘못된 순서·정순서 완료·기한 초과, 왕복 경로·완주·중도 해제, 스피너 양방향 완수·버튼 해제·예고·정지·잘못된 반경·갑작스러운 각도 이동·미완료를 확인한다. 검사에서 저장한 튜토리얼과 기믹 화면으로 안내 배치도 확인한다.

`tests/run_story_checks.ps1`: 38개 대사 배열 2118개 항목(공유 엔딩 중복 포함), 기존 CG 7개·스토리 애니메이션 22종·표현 변형 22종과 대사 표시·입력·초기화를 검사한다. `tests/run_stat_checks.ps1`: 4/5/6/7게임 보상·엔딩 경계를 검사한다.

왕복 슬라이더의 같은 길 되돌아오기와 반전 화살표는 [osu!의 반복 슬라이더](https://osu.ppy.sh/wiki/en/Gameplay/Hit_object/Slider/Repeat_slider)를 참고했다. 버튼을 누른 채 공의 범위를 따라가는 기본 동작은 [osu! 슬라이더 설명](https://osu.ppy.sh/wiki/en/Gameplay/Hit_object/Slider)을 따른다. 회전 방향 선택·누른 채 회전·진행 게이지는 [osu! 스피너 설명](https://osu.ppy.sh/wiki/en/Gameplay/Hit_object/Spinner)을 참고했다. 본 게임의 스피너는 정해진 회전 수를 완수하면 300점이며 추가 회전 보너스는 없다. 앵콜은 같은 위치에서 두 번 클릭하는 기존 규칙을 유지한다. 화살표·접근 원·발광은 GDI+로 직접 그리며 외부 스킨 이미지를 복사하지 않는다.

사람이 전곡을 직접 플레이하며 체감 난이도와 음표별 청감을 조정한 단계는 아니다. 현재 채보는 파형 분석과 자동 판정 검사를 통과한 초안이다.
