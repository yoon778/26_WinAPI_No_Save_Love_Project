# CODEX_PROMPTS.md

## 1. 코드 분석만 시킬 때

현재 프로젝트 구조를 분석해줘.
아직 파일은 수정하지 말고, 다음을 정리해줘.

1. 전체 씬 흐름
2. GameManager가 관리하는 전환 구조
3. 각 Scene 클래스의 역할
4. 지금 구조에서 위험한 부분
5. 수정이 필요한 파일 후보

반드시 파일 수정 없이 분석만 해줘.

## 2. 특정 기능 구현시키기

다음 기능을 구현해줘.

목표:
- [여기에 기능 설명]

수정 범위:
- 가능한 한 [파일명] 안에서만 수정
- 필요한 경우에만 관련 헤더 수정
- 팀원이 담당하는 파일은 수정하지 말 것

규칙:
- GameManager만 씬 전환을 담당한다.
- Render 안에서 이미지 로드 금지.
- 새 코드에는 한국어 주석을 달 것.
- 큰 구조 변경 없이 최소 수정으로 해결할 것.

작업 후 알려줄 것:
1. 수정한 파일
2. 수정한 함수
3. 왜 그렇게 수정했는지
4. 수동 테스트 방법

## 3. 버그 원인 찾기

다음 문제가 발생한다.

증상:
- [예: 결과 화면에서 스탯이 이상하게 출력됨]

원하는 작업:
1. 관련 파일을 먼저 읽고 원인을 추정해줘.
2. 바로 수정하지 말고 수정 계획을 먼저 제시해줘.
3. 원인이 확실한 경우에만 최소 수정해줘.
4. 수정 후 수동 테스트 체크리스트를 작성해줘.

주의:
- 전체 구조를 갈아엎지 말 것.
- 기존 함수 이름을 함부로 바꾸지 말 것.

## 4. 코드 리뷰용

아래 기능 구현이 과제 기준에 맞는지 리뷰해줘.

확인할 것:
1. 컴파일 위험
2. 무한 루프 가능성
3. 메모리/GDI 누수 가능성
4. Win32 메시지 처리 위치가 적절한지
5. GameManager와 Scene 책임 분리가 지켜졌는지
6. 팀 작업 중 충돌 위험이 있는지

파일은 수정하지 말고 리뷰만 해줘.
